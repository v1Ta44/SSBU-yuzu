# F11 切换时延迟面板不可见：候选方案（2026-10-26）

状态：用户已明确入口为 F11，并裁定“全屏或无边框时，都让面板临时置顶”。已实施、补回归并更新试用程序，最终报告见 YUZU_F11_PANEL_FIX_2026-10-26.md。以下保留提案阶段的调查和候选记录。

## 路径差异

runtime/display.c::toggle_fullscreen 在 F11 进入时设置 WS_POPUP，并用 HWND_TOP / SWP_FRAMECHANGED / SWP_NOOWNERZORDER 覆盖当前显示器；它没有将游戏窗口设为 TOPMOST。菜单 window_mode_set 则在调用 toggle_fullscreen 后额外处理 TOPMOST / NOTOPMOST。两条入口不能互相代替验证。

extensions/net_delay/ui/win32_panel.cpp::sync_overlay_layer 目前只让面板的 TOPMOST 标志等于游戏。F11 无边框模式下，游戏不置顶，面板也不置顶；现有逻辑没有为这种屏幕覆盖方式单独给面板一个上层位置。这是明确的覆盖范围缺口，但不能仅凭源码或样式标志断言捕获了用户现场的完整故障根因。

用户最新 logs/20261026-215552_LAPTOP-D3E75748_play 已包含多次 display: F11: borderless over the monitor / window，确认应围绕真实 F11 调查。页面日志存在展开 / 收起；旧日志没有同步记录焦点、位置和遮挡，不能精确对应哪次用户看不见。

## 建议行为

1. 游戏为无边框样式且面板应当显示时，仅将面板临时置顶，游戏窗口的置顶策略不变。
2. 面板收起或游戏失焦时照常隐藏；若游戏本身不置顶，撤掉面板的临时置顶。切回普通窗口也恢复普通层级。
3. 菜单设置的置顶全屏继续沿用其现有策略；隐藏面板时保留游戏本身的置顶状态，避免 Windows 所有者窗口连带降级。
4. 位置计算、F8 选值、保存设置及减延迟算法保持现有逻辑，窗口调整使用 NOACTIVATE，输入焦点仍归当前操作窗口。

改动范围只有面板的层级决策，以及必要的 F11 回归；不修改上游 display.c、图形渲染或第三方 mod。
