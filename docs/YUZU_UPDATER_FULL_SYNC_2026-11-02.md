# 完整更新与自动清理实现（2026-11-02）

用户裁定：忽略本地旧文件一致性，以更新后程序符合新版为目标；随后要求增加自动清理。已在 yuzu-dev 实施并完成专项检查，未替换现有试用程序，未发布更新包或合入稳定分支。

## 更新规则

- 只选择 / 接受完整更新包，不依赖旧 build_id 或旧文件哈希，不使用省略文件的差异补丁。发行生成器默认 full，明确拒绝 patch / both；兼容保留 --base 参数，但不打开该目录，--force-file 不再影响范围。
- 新包完整提供目标清单中的所有受管理文件，原文件修改、缺失、JSON 内容变化或已经是目标版本都可安装。签名清单指定的删除路径不再要求匹配旧哈希，原来就不存在也可成功；已有内容先备份。
- 本地功能组合不再用于拒绝完整更新，旧资源后端标志可以迁移到新标志；仍检查新包的宿主功能、目标 EXE 哈希和新版本记录彼此匹配。
- 本地 manifest / version / host 构建记录损坏不再拦住修复；有效的已安装签名记录用于显示版本和防止意外降级。同发行序号允许重新安装修复。原已安装记录原样保存，损坏或格式不同也可精确回滚。
- 签名、目标文件哈希、目标清单完整性、保护路径、防链接越界、磁盘空间、文件占用、备份和中断恢复保留。旧文件仍会为了记录实际备份和核对恢复而计算哈希；这些哈希不参与判断“是否符合旧发行”。
- “跟新版一致”指目标清单中的发行文件，以及签名明确列出的退役文件处理；个人存档、配置、资源 mod、缓存和清单外个人文件保留。同名路径如果已在签名目标程序清单中，则备份后由新版覆盖。
- 更新协议最低辅助程序版本提升为 2，与游戏 / 发布版本号无关。旧 Console 内嵌旧 helper，不能因下载了新版文件就提前改变旧规则；正式交付仍需配套新版 helper / Console 和完整修复入口。

## 自动清理

清理只在独立更新器安装成功后触发，在安装目录独占锁仍持有期间进行。先核对安装结果和当前回退备份；任一检查失败不删除恢复资料。

| 类别 | 成功后的处理 |
| --- | --- |
| updates/downloads 中更新器生成的 .download | 删除 |
| updates/staging 中更新器生成的解压目录 | 删除，包括以前失败遗留的暂存 |
| updates/backup | 保留最新一次已完成更新的备份，删除更早备份 |
| updates/history | 删除已不再保留对应备份的旧事务历史 |
| updates/helpers | 删除旧辅助程序目录；跳过本次正在运行的 helper |
| 手动下载 / 导入的外部 ZIP、未知命名文件 | 保留 |
| 当前 transaction、installed、来源配置和用户资料 | 保留 |

目录名须符合更新器生成的标识。先核对绝对路径属于指定 updates 子目录，再逐层处理，拒绝符号链接 / Windows 联接点。暂存文件占用或清理失败只写入 updates/cleanup-result.json，不把成功安装改报失败。当前 helper 的小目录会在后续成功更新时清理。

安装失败 / 中断时保留资料用于恢复；这些临时资料可在以后一次成功更新时清理。自动清理降低更新后的长期占用，不消除下载、解压和备份同时存在时的临时空间需求。正常清理后主要额外空间为一份最近回退备份，不会按每次成功更新无限积累完整包。
