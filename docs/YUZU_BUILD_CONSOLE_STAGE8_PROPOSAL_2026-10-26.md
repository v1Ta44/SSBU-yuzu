## 提请裁定的三处修正

### 1. 同一设置出现多次时，F1 修改可能重启后失效

具体例子：配置文件有两行 vsync=auto，F1 改成 off，runtime/gfx_options.c 的 gfx_ini_set 只更新第一行，保留末行 auto。图形读取和 Console 图形读取使用最后一行，因此重启后仍是 auto。已用实际 F1 写入函数在独立配置中复现。

联机读取另有既有“第一处有效行”的规则；独立探针也明确测出 Console 网络启动和原生网络均取第一行，不能据此声称这两者当前互相冲突。问题主要是重复行与不同设置读取规则结合，导致写入不能一致生效。

建议只调整 gfx_ini_set：修改某项时同步更新所有同名有效设置行，与 Console 现有写入策略保持一致；其余设置、注释与顺序保留。写入缓冲应按实际增长计算或安全扩容，避免多行替换时超出容量。不重写联机协议，不更改全局读取优先级。

验证：单行 / 重复行、缺失键、大小写与空格、注释和未知项、追加与长值容量；证明旧实现对重复 vsync 的反例失败，新实现重启读取一致。保存联机项时同样更新全部重复行。

### 2. 预编译运行时可能静默忽略减延迟开关

具体组合：--runtime 配合 --without-yuzu --with-latency-slider。现有 load_runtime 只拒绝 Yuzu，step_link 的预编译分支直接复制上游 EXE 并返回，绕过 build_extension。独立假包 / 空游戏 DLL 夹具复现：流程返回成功，命令只有 gamedll，未调用扩展构建，未生成 latency_slider.dll。这不是当前试用程序的装载失败；属于构建入口的参数组合缺口。

建议在解包 / 复制前明确拒绝“预编译上游宿主 + 要求自有减延迟”的组合，提示去掉 --runtime 从源码构建，或显式关闭自有减延迟。源构建流程保留，纯上游预编译安装保留。增加“在任何复制前拒绝”的回归。

### 3. 修复共用测试接口的重复定义

tests/network_protocol.c 上次恢复减延迟时补入了 extra_import_lookup；tests/console_network_bridge.c 原来已有该接口，包含共用文件后重复定义。这是上次补测试接口引入的测试回归，不是游戏运行时接口冲突。

建议保留一个共用实现，移除重复定义或按调用方显式选择测试桩，确保没有插件导出的夹具仍返回正确的缺失结果。不改生产符号查找逻辑。原测试正常编译后重跑原生管道和 Rust 两项启动 / 重启检查。
