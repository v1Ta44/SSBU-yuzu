## 建议修改，按四部分验收

### A. 修正不必要的旧文件限制

- 签名目标哈希已经匹配的目标路径允许继续，仍检查签名、路径和可写性；整体更新不能因此漏掉版本记录及其他文件。备份以实际安装前内容为准，回滚也恢复实际内容。
- 仅对指定的生成构建记录引入“可信 JSON 语义一致”路径，忽略空白 / 键顺序。不能笼统忽略全部 .json，也不能忽略 binary/source/artifact 哈希、功能字段等实际变化。
- 可信依据由签名更新计划携带旧构建记录的语义指纹等必要资料；未随补丁更换但参与基础校验的记录也要覆盖。旧包只有字节哈希而无法确认语义时，不猜测放行，转完整修复。发布生成器必须同步产生这些资料。
- 完整更新允许修复由当前发行清单明确拥有、且更新包确实提供的路径，包括缺失或内容不匹配的文件，先备份再替换；未知同名文件仍报告冲突。补丁仍要求未替换的执行文件与基础匹配，避免拼出不完整混合版本。
- 删除操作单独审核：不以“更新更宽松”为由删除未知或用户修改的文件。

保持目标包签名与目标文件逐字节哈希、路径防穿越、用户目录保护、运行占用、备份校验、中断恢复与回滚校验。对下载损坏、签名错误不做完整包重试掩盖。

### B. 完整包回退和旧更新器接入

- 当前 Console 按 build_id 优先选补丁；校验基础不符时没有实际重新选择完整包的流程，错误文字建议完整包却不保证能用。加入明确的“此补丁不适用，可改用完整修复包”状态；只在基础兼容问题时转用签名完整附件，重新下载 / 校验并展示完整包体积。
- 不强行把所有错误变为回退：磁盘不足、文件占用、签名或下载损坏应给具体处理提示。
- 旧版更新器会在换上新更新器之前执行旧规则，自更新包不能自动解除已经命中的旧限制。提供独立的新版更新辅助程序 + 签名完整修复包入口，可先验证更新再备份安装，保留旧目录和用户资料。
- 需要新语义字段的发行明确提高 minimum_updater，避免旧程序忽略字段后按旧规则误判；Console 内嵌和包内 helper 必须是同一版。正式对外更新只在另行获得发布授权后进行。

### C. 允许已知的个人版迁移，不放开任意组合

- 当前 updater::Features 和 release_update.py 只比较 resource_mods / latency_slider；旧资源后端 true 与新版上游 Skyline 路线 false 不相等，Console、原生更新器及发行生成器三处都会阻止这一迁移。
- 用明确的签名迁移信息列出允许的旧 build_id / 功能组合 → 新组合，保持游戏版本 / 平台兼容；补充 Skyline、Yuzu 等关键运行能力，按老记录缺字段时的已知版本规则处理，不随意把缺字段当成功能关闭。
- 生成新版与旧版两种来源的检查 / 安装 / 回滚反例，证明只开放批准的迁移路径。旧个人资源后端作为发行程序文件可在备份后撤出；用户 mod、设置、存档不属于删除对象。

### D. 补齐 Skyline / ARC 打包链

- 当前 scripts/package.py 创建 mod 管理目录，却没有打包 plugin_bin 的注册表和编译后的 ARC DLL，也未建立原样 NRO 的受管理发行范围。scripts/release_update.py 和原生 managed 路径规则均拒绝这些路径。
- 增加经核对的插件注册表、对应编译 DLL、原样 ARC 插件及必要运行依赖；注册表导出时移除本机绝对路径，按包内相对路径关联。实际第三方原文件不改内容。
- 只把指定的发行插件文件纳入管理，不能将整个 SD 或任意插件目录开放给更新器；sd/ultimate/mods、disabled/trash、配置、存档、缓存、日志保持用户所有。
- 校验 Python 生成器与 Rust 安装器路径规则一致；在没有开发目录依赖的隔离便携包里检查启动、ARC 挂钩和原样资源包加载。不能只用游戏裸启动成功证明 mod 加载完整。
