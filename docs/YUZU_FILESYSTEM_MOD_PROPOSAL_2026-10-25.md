# 修订方案：上游 Skyline / ARCropolis 加载，Console 管理（2026-10-25）

架构裁定：用户明确要求沿用上游 Skyline 加载 ARCropolis，再由 ARCropolis 加载资源 mod；本地只保留 Console 的 mod 管理。此前“接回个人虚拟归档资源后端”的方案作废。用户于 2026-10-25 回复“同意”，下列范围已获批准，实施和验证进行中。

## 上游依据

本地 main 的 docs/SKYLINE.md 已说明完整入口：

- 插件目录：sd/atmosphere/contents/01006A800016E000/romfs/skyline/plugins。
- 资源包目录：sd/ultimate/mods。
- tools/nro/build_plugins.py 转换插件；必要时按 skyline_sites.log 使用 relift_sites.py 为游戏及脚本模块生成对应 Hook。
- SSBU_SD 指定 SD 目录；SSBU_PLUGIN_BIN 指定生成的插件目录；SSBU_SKYLINE=0 关闭插件。

这次直接沿用这些加载与生成工具。上次已验收的功能测试版没有准备这条插件链，不能把它的实机结果当成 ARCropolis 已通过。

## 加载与管理的分工

1. 游戏侧使用上游文件系统、Skyline、ARCropolis 处理资源加载和替换。
2. 个人虚拟 data.arc 读取、补丁缓存和 ssbu_mod_backend.dll 不再接入游戏，也不再作为 Console 管理页的依赖。
3. Console 管理本地包、界面别名和启用状态，为上游指定目录与配置提供入口。原来用于显示分类或导入的辅助代码可迁入 Console，资源替换算法不再保留为加载路径。
4. 已验收的联机、统一游戏名字与后台运行功能继续保留。nnfs.c 以上游文件系统和账号接口为基础，单独保留统一名字衔接。

## Console 管理细节建议

- 保留列表、文件夹/ZIP 导入、界面别名、启用/停用、打开目录和删除到回收区。
- 显式设置上游读取的 SD 目录；启用的包放入实际 ultimate/mods 目录。
- 停用区与回收区放在 ARCropolis 资源扫描目录之外，防止误加载。包的管理位置可以改变，config.json、模型、贴图、音频和 plugin.nro 等包内文件保持原样。
- UI 别名等管理信息独立保存，不写入第三方包。
- 游戏运行时继续限制修改，只允许查看和打开目录。
- 优先级和换槽原来由个人后端实现；先核对实际使用的 ARCropolis 原生能力。没有可靠对应时，第一阶段隐藏这些控件，不保存看似生效却无人读取的旧设置，也不另写一套资源替换实现。
- 原有 Console 配置先保留并备份；迁移时导入可对应的目录、别名和启用状态，不擅自移动或改写原工作目录的包。
- 界面检查插件链是否准备好，并提供相应状态；兼容性不再按旧资源后端的能力表判定。

## 预计改动范围

- runtime/nnfs.c：采用上游文件系统，移除个人资源拦截；保留统一名字衔接。
- runtime/mod_resources.c/.h 及其引用：撤出旧加载通路，清理关联初始化/接口；必要的 Console 管理辅助逻辑迁入 Console。
- tools/console/src/mods.rs、相应 UI、启动设置：去除对旧后端 DLL 和 resource_mods 标志的依赖，连接 SD 目录及原生 mod 管理。
- tools/lifter/build.py、scripts/setup.py 及相关构建记录：撤出个人资源后端构建依赖，沿用上游插件构建流程。核对打包侧引用，避免把旧 DLL 误作新加载器的必需组件。
- 相关测试与当前说明文档：验证管理功能和真正的插件加载路径。

具体受影响文件在实施前后列清；旧稳定 yuzu 分支与其本地资料保留，不用清理稳定目录的方式移除旧方案。

## 验证步骤

1. 无插件/无 mod 时检查原版启动，以及已验收的联机、名字和后台运行回归。
2. 对 Console 的导入、别名、启停、软删除和运行中限制做独立目录检查，核对原包所有文件哈希不变。
3. 以原样 ARCropolis 与资源包准备独立 SD 目录，按上游工具转换插件、采集并生成需要的 Hook。
4. 核对真实插件加载日志与 Hook 状态，不能只凭 DLL 存在或 Console 开关判断成功。
5. 通过实际画面或其他可核验资源替换结果确认启用/停用确实影响游戏，再交用户实机验收。

本项不处理剩余图形冲突、延迟模块或 Yuzu 回滚，不授权发布或合入稳定分支。
