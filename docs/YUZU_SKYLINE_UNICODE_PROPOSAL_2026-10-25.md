# 中文包目录问题：调查、修复与验收（2026-10-25）

状态：用户已明确回复“修复”，本方案已批准并实施。67 项文件系统检查通过，44 个中文包均能进入，加载动画与火狐 c00 角色替换均已实机确认；用户于 2026-10-25 明确确认“验收通过”。实施与验证记录见 YUZU_SKYLINE_UNICODE_FIX_2026-10-25.md。原始用户模组未改动。

## 用户反馈与结论

用户在本机隔离验收版的启用目录放入新 mod，但游戏里看不到任何替换。当时的首次验收未通过。此后已按用户授权修复，修复版于 2026-10-25 获用户重新验收通过；首次失败证据保留。

已确认当前这批包的共同阻断是路径编码：Switch/ARCropolis 使用 UTF-8，宿主目录枚举返回 UTF-8 名字，后续宿主文件系统却将同一字节串交给 Windows ANSI API。本机 ANSI 代码页为 936（GBK），因此中文路径被误解读，真实目录被判为不存在。此前仅用英文包名验证，未覆盖这一情形。

## 直接证据

- 实际 launcher.ini 的 SSBU_SD 与用户放包目录一致，不是 Console 和游戏读取不同目录。
- 两次用户运行：review/logs/20261025-025202_LAPTOP-D3E75748_play 和 20261025-025929_LAPTOP-D3E75748_play。插件加载、50 处生成挂钩、mods 文件系统注册均出现；根目录列出 44 个包，但两份 boot_trace.txt 都没有进一步进入任意包的目录记录。
- 44 个包名均包含中文。在真实路径上只读调用 GetFileAttributesW，44/44 存在；将相同路径 UTF-8 字节传给当前使用的 GetFileAttributesA，0/44 存在，错误为 2 或 123。
- 共检查 2122 条资源文件路径，最长 194 个 UTF-8 字节，全部低于当前 260 字节缓冲区上限，未发现路径截断这一替代原因。
- 原生预设文件当前为 []，这不能解释操作系统接口对现有目录返回不存在；应先修复已复现的路径错误，再判定后续原生选择及各包兼容情况。
- 全部机器可读结果：build/skyline-unicode-20261025/path-encoding-results.json。没有改名、搬动、删除或修改用户包内容。

## 源码位置

runtime/nnfsdir.c 的 fs_OpenDirectory：Windows Wide 枚举后，目录条目通过 CP_UTF8 交给插件；进入下一层前，又将组合路径按 CP_ACP 转给 Windows，编码不一致。

runtime/nnfs.c：exists/is_dir 使用 GetFileAttributesA；fs_dir_roots 和 fs_GetEntryType 经过它们判断是否存在；fs_OpenFile 使用 CreateFileA。只改单一枚举步骤无法修好后续文件打开。

## 拟实施范围

1. 在 Windows 文件系统兼容边界统一编码：游戏/插件路径保持 UTF-8，调用 Windows 文件系统时可靠转换为 UTF-16，使用对应的 Wide 接口；同时正确处理从系统环境和挂载根目录进入的路径，避免混合 UTF-8 与本机代码页。
2. 联动检查 nnfs.c、nnfsdir.c 的目录存在性、逐层枚举、文件打开及关联路径操作。可以抽出很小的共用转换层；保持上游 FSA 分派、存档提交/恢复算法与已验收名字逻辑。
3. 添加能复现本次失败的中文/英文路径检查，在独立诊断目录以原样包复验：重新扫描全部 44 个包，确认能进入包内资源目录；再选代表包确认资源实际读取/替换、启停有效，核对每个原文件哈希未变。测试 Console 启停和现有存档日志，避免仅修好枚举却破坏打开或保存。
