## 用户裁定与实现

用户明确要求：窗口部分先接上游修复，再在上游实现逻辑下做后台运行；手柄部分先写完整数据，再执行输入诊断。

### 窗口：以上游状态机为基础

runtime/nnmisc.c 的冲突先采用 main 内容，保留上游窗口可见性与前台检测、屏幕外/不可激活窗口过滤、Linux/macOS 条件分支、独立 watcher、通知队列、事件唤醒和退出请求处理。在此基础上增加一个后台策略，选择上游已有的 NoSuspend 模式。

默认情况下，切出窗口对应的真实焦点状态仍会通过通知队列更新；最小化也会更新为后台状态。watcher 持续运行，运行时不因为这些状态挂起游戏线程。游戏原来请求的焦点处理模式仍被保存，仅通过一个有效模式函数决定当前策略；通知与是否可运行使用同一个有效模式。

| 配置 | 行为 |
| --- | --- |
| 未设置或空的 SSBU_FOCUS_NOTIFY | 使用上游 NoSuspend 路径，保留焦点跟踪和通知，运行时不因切出/最小化挂起游戏线程 |
| SSBU_FOCUS_NOTIFY=1 | 使用游戏请求的上游原始模式，按对应规则通知、暂停和恢复 |
| SSBU_FOCUS_NOTIFY=0 | 保留上游显式关闭焦点跟踪的选项 |

这和旧个人实现默认停掉焦点跟踪有所不同。当前默认后台运行仍使用上游的事件与状态处理。后台运行不改变键盘/手柄的前台输入归属规则。

窗口关闭和退出请求代码本身保持上游实现，包括退出处理区间的嵌套、退出消息、待退出时保持可运行以及最外层区间结束后的退出。

nnmisc.c 中自动合并保留的 ssbu_desired_language_code 资源兼容接口未在本阶段改动；mod 整合仍属于后续范围。

### 输入：完整写入后观察

runtime/nnhid.c 保留上游 GameCube 两个模拟扳机的写入、F1 手柄控制和原有普通手柄处理。个人 input_trace_pad 放在完整数据写入后调用；断开连接时继续记录释放状态。

本阶段不改变已有输入记录格式。GameCube 两个扳机通过游戏接收缓冲区及观察回调断言验证；现有 CSV 仍记录原有按键、摇杆和连接属性字段，不新增模拟扳机列。

## 后续补充：游戏自身的失焦停帧（2026-10-26）

本阶段的 NoSuspend 默认策略只覆盖了运行时不挂起线程；游戏在收到 OutOfFocus（2）后还会自行清除主循环事件。后续完整整合时暴露为偶发加载停滞，已由用户授权修复。现只在默认后台策略下将面向游戏的状态 2 适配为 Background（3），内部真实焦点、通知及显式上游模式保留；新增真实游戏事件门控回归及完整游戏前后对照。具体证据、修复和当前独立试用入口见 YUZU_BACKGROUND_FOCUS_FIX_2026-10-26.md。本段不改写此前用户验收事实，并补全当时未覆盖的普通失焦路径。
