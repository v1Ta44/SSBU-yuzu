状态：此保留个人优化的提案已被用户“废弃个人版的部分”的明确裁定替代。实际执行为完整采用 main 的 runtime/nvn_vk_m4.c，撤出个人着色器内存优化；以下旧方案保留为历史，当前实施与验证见 YUZU_GRAPHICS_STAGE7_2026-10-26.md。

## 用户会看到什么

保留上游对部分 AMD 显卡创建着色器管线失败的恢复措施，同时接回个人版的着色器内存回收。窗口、正常游玩和现有图形设置维持当前流程；本项不增加新的渲染模式或延迟调节项。

当前独立验收程序的图形副本一直采用上游基线，因此此前游戏能够运行，不代表分支里的图形冲突已经合并或个人内存优化已通过本轮验收。

## 实际冲突与建议

runtime/nvn_vk_m4.c 只有一处文本冲突，位于 stagelib_get 的阶段管线库创建步骤。文件其余位置已自动接入个人资源回收代码，因此不能只选任意一边结束冲突。

| 要保留的行为 | 具体做法 |
| --- | --- |
| 上游创建失败恢复 | 初次失败后最多重试三次；最后一次不使用驱动管线缓存。若仍失败，保留 no_stage_libraries.txt 标记及重新启动后使用完整管线的方案。 |
| 个人着色器模块回收 | 创建期间持有模块，全部重试结束后恰好释放一次本次持有；成功后继续执行原有可回收模块清理。 |
| 管线结果交接 | 所有创建和重试统一写入局部 got，成功后再在原有锁内交给共享 lib 并置为可用，避免直接取上游冲突块后又被未初始化的局部结果覆盖。 |
| 个人管线库预算 | 保留默认 4096 的数量预算；只清理未被管线引用、没有链接使用者且足够久未使用的库；保留对战避让、后台销毁和原有关闭开关。 |
| 现有缓存和兼容性 | 保留上游 AMD 顶点格式/缺失动态顶点输入支持、缓存分组及驱动失败标记；不为此次合并清空用户缓存。 |

内存优化的代码与历史记录主要涉及宿主着色器对象和进程私有内存，不能直接宣传为减少相同数量的独立显存。历史 NVIDIA 测量不当作本轮新显卡/新版本的实测收益。
